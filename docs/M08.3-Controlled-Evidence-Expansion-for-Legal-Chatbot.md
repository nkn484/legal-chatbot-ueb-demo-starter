# PROMPT: IMPLEMENT CONTROLLED EVIDENCE EXPANSION FOR LEGAL RAG

## 1. Vai trò

Bạn là **Senior AI Architect + Tech Lead + Backend Engineer** chịu trách nhiệm cải tiến hệ thống Legal Chatbot hiện tại.

Nhiệm vụ là thiết kế và triển khai cơ chế:

> **Evidence Gap Detection → Controlled Evidence Acquisition → Validation → Corpus Expansion → Re-Retrieval → Grounded Answer**

Mục tiêu là cho phép hệ thống xử lý trường hợp:

- câu hỏi thuộc đúng phạm vi pháp lý;
- nội dung câu hỏi hợp lệ;
- Internal Retrieval không tìm thấy đủ evidence;
- tài liệu cần thiết chưa tồn tại trong corpus hiện tại;
- hệ thống có khả năng chủ động tìm tài liệu pháp lý phù hợp từ nguồn được phép;
- kiểm tra và xác thực tài liệu;
- sử dụng tài liệu vừa tìm được cho câu hỏi hiện tại;
- ingest tài liệu hợp lệ vào Evidence Database để tái sử dụng cho các truy vấn sau.

Không được thiết kế theo mô hình:

```text
LLM → Internet → kết luận → lưu thẳng DB
```

Phải sử dụng mô hình:

```text
LLM → Search Plan
        ↓
Controlled Source Retrieval
        ↓
Source Validation
        ↓
Temporary Evidence
        ↓
Answer
        ↓
Validated Corpus Ingestion
```

# 2. Nguyên tắc kiến trúc bắt buộc

## 2.1. LLM không phải nguồn evidence

LLM chỉ được phép:

- hiểu câu hỏi;
- phân rã legal issues;
- tạo search query;
- mở rộng từ khóa;
- đề xuất loại văn bản cần tìm;
- đánh giá semantic relevance;
- hỗ trợ ranking candidate.

LLM không được phép:

- tự tạo nội dung pháp luật;
- tự xác nhận một nội dung là quy định pháp luật;
- ghi kết luận do LLM sinh ra vào Evidence Database;
- coi nội dung search snippet là evidence;
- coi nội dung từ website không xác thực là authoritative evidence.

Nguyên tắc cứng:

> LLM quyết định **cần tìm gì**, nhưng không quyết định **cái gì được công nhận là evidence pháp lý**.

# 6. Evidence Sufficiency Gate

Đây là module quan trọng nhất.

Không được dùng logic đơn giản:

```python
if similarity < threshold:
    external_search()
```

Evidence Sufficiency phải là composite evaluation.

Tối thiểu đánh giá:

```text
1. issue_coverage
2. source_authority
3. temporal_validity
4. passage_support
5. document_completeness
6. legal_relation_completeness
7. conflict_status
8. retrieval_confidence
```

Ví dụ output:

```json
{
  "status": "INSUFFICIENT",
  "score": 0.54,
  "missing_issues": [
    "work_permit_requirement",
    "exemption_rules"
  ],
  "reasons": [
    "Primary law found",
    "Implementing regulation missing"
  ]
}
```

Không yêu cầu score phải do LLM tạo.

Ưu tiên deterministic rules + metadata.

LLM chỉ hỗ trợ trong những trường hợp semantic assessment cần thiết.

# 8. Phân biệt RETRIEVAL_MISS và CORPUS_GAP

Đây là yêu cầu bắt buộc.

## RETRIEVAL_MISS

Có khả năng tài liệu đã tồn tại trong DB nhưng retriever không lấy ra được.

Trước external search phải thử Retrieval Recovery.

Thứ tự:

```text
semantic retrieval
    ↓
hybrid retrieval
    ↓
lexical search
    ↓
exact citation search
    ↓
metadata search
    ↓
query expansion
    ↓
legal relation traversal
```

Không external crawl ngay chỉ vì vector similarity thấp.

---

## CORPUS_GAP

Chỉ xác định `CORPUS_GAP` sau khi:

- retrieval thông thường thất bại;
- query expansion thất bại;
- lexical/metadata search thất bại;
- exact citation lookup thất bại;
- legal relationship traversal không bổ sung đủ evidence.

Khi đó mới kích hoạt:

```text
Controlled External Evidence Acquisition
```

# 28. Core orchestrator

Thiết kế logic tương đương:

```python
async def answer_legal_query(query):

    plan = await query_planner.plan(query)

    evidence = await retrieval.search(plan)

    sufficiency = await evidence_gate.evaluate(
        plan=plan,
        evidence=evidence,
    )

    if sufficiency.is_sufficient:
        return await grounded_answer(
            query=query,
            evidence=evidence,
        )

    recovered = await retrieval_recovery.run(
        plan=plan,
        missing=sufficiency.missing_issues,
    )

    sufficiency = await evidence_gate.evaluate(
        plan=plan,
        evidence=recovered,
    )

    if sufficiency.is_sufficient:
        return await grounded_answer(
            query=query,
            evidence=recovered,
        )

    gap = await gap_classifier.classify(
        plan=plan,
        evidence=recovered,
    )

    if gap != CORPUS_GAP:
        return safe_no_evidence_response()

    search_plan = await external_search_planner.plan(
        plan=plan,
        missing_issues=sufficiency.missing_issues,
    )

    candidates = await acquisition.search(search_plan)

    validated = await evidence_validator.validate_many(
        candidates
    )

    if not validated:
        return safe_no_authoritative_evidence_response()

    temp_evidence = await temporary_evidence.build(
        validated
    )

    combined = merge(
        recovered,
        temp_evidence,
    )

    final_sufficiency = await evidence_gate.evaluate(
        plan=plan,
        evidence=combined,
    )

    if not final_sufficiency.is_sufficient:
        return safe_insufficient_evidence_response()

    answer = await grounded_answer(
        query=query,
        evidence=combined,
    )

    await ingestion.enqueue(validated)

    return answer
```

Điều chỉnh theo async architecture hiện tại.

# 36. Nguyên tắc cuối cùng

Ba boundary tuyệt đối:

```text
1.
SEARCH RESULT ≠ EVIDENCE

2.
LLM OUTPUT ≠ LEGAL AUTHORITY

3.
VALIDATED OFFICIAL DOCUMENT
        ↓
CAN BECOME EVIDENCE
```

Mục tiêu cuối:

> Legal Chatbot có khả năng tự mở rộng corpus dựa trên nhu cầu sử dụng thực tế, nhưng việc mở rộng phải có kiểm soát, có nguồn gốc, có validation, có version, có provenance và không làm giảm độ tin cậy của Evidence Database.

Không tối ưu hệ thống chỉ để tăng answer rate.

Ưu tiên theo thứ tự:

```text
Correctness
→ Evidence integrity
→ Provenance
→ Temporal validity
→ Retrieval quality
→ Coverage
→ Latency
```

Nếu phải lựa chọn giữa:

```text
trả lời nhanh nhưng evidence yếu
```

và:

```text
không kết luận vì chưa đủ authoritative evidence
```

hãy chọn phương án thứ hai.
