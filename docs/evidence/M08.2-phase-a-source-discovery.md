# M08.2 Phase A — Exact source authorization, isolation and discovery evidence

## Scope

Phase A implemented the closed, exact VBQPPL document authorization model and production retrieval
source isolation. User approval covered SOAP discovery only for the 32 document numbers in
`docs/M08.2-benchmark-ready-corpus-plan.md` §3.2. It did not authorize discovery of any other number,
document fetch, ingestion, TLS relaxation, HTTP fallback or trusted-manifest mutation.

## Implemented controls

- `contracts/source-registry.json` remains source-level lifecycle/transport/operation authority.
- `contracts/vbqppl-read-manifest.json` is the sole document-level authority:
  - 32 SOAP `DISCOVERY_APPROVED` entries;
  - only `63/2025/QH15` remains fetch-approved;
  - SOAP and REST fetch permissions are separate per `(document_number, transport)`.
- Discovery uses non-fetchable candidates and a separate discovery port/CLI.
- `list_documents()` returns only fetch-approved refs and performs zero discovery calls.
- Unauthorized discovery/fetch paths produce zero network calls.
- Production original and expansion retrieval filter by the same registry-derived `ACTIVE` source set;
  test/synthetic sources require explicit test-only injection.

## External blocker diagnosis

`https://ws.vbpl.vn/vbqppl.asmx?WSDL` resolves to the remote server, but TLS hostname validation fails.
The presented certificate is issued for `*.moj.gov.vn` / `moj.gov.vn`, not `ws.vbpl.vn` or
`*.vbpl.vn`. This is an identity mismatch, not an expired-certificate condition.

No authoritative, TLS-valid replacement SOAP endpoint was verified. Tested obvious valid-host paths on
`vbpl.vn` returned `404`; an inferred `ws.moj.gov.vn` hostname is not a usable published endpoint.

Status:

```text
BLOCKED_EXTERNAL: SOURCE_UNAVAILABLE_TLS_IDENTITY_MISMATCH
```

The implementation intentionally did not disable TLS verification, use HTTP, pin the mismatched
certificate, infer an unpublished hostname, or use SOAP discovery output to authorize fetch.

## Gate A remediation

Initial Gate A review accepted authorization/isolation behavior but found stale singleton and duplicate
authority assumptions. Remediation completed:

- removed hard-coded discovery-number/fetch-identity literals from Python; the tracked manifest is the
  sole document-level authority;
- SOAP and REST adapters now accept bounded zero-or-more transport-specific fetch refs;
- future approved fetch entries require manifest changes, not adapter code changes;
- REST fetch selects and revalidates each reference's exact path/canonical URL;
- `LegalSourcePort` and ingestion now require `FetchApprovedDocumentRef`, rejecting plain references and
  discovery candidates as fetch capabilities.

Post-remediation validation is the `479 passed, 6 skipped` result above. The external TLS blocker and
zero-candidate discovery outcome are unchanged.
