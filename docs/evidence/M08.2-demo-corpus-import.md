# M08.2 — Manual snapshot corpus import evidence

Date: 2026-08-21

## Approved claim

Import all 1,104 rows from `RAWDATA_QPPL`, `RAWDATA_VNU`, and `RAWDATA_UEB` into a durable
catalog, while allowing only successfully downloaded, extracted/OCR-processed, chunked, and indexed
documents to become chatbot evidence.

Live VBQPPL ingestion is disabled by default. The existing VBQPPL adapters and `LegalSourcePort`
boundary remain intact.

## Implemented evidence path

1. Deterministic workbook parser validates an exact total of 1,104 records.
2. PostgreSQL migration `0007_demo_corpus_catalog` stores all rows and processing states.
3. Google Drive files are fetched only through `ManualSnapshotSourceAdapter`, which implements
   `LegalSourcePort` and revalidates every catalog-derived reference.
4. PDF text extraction runs first; scan-only PDFs become `OCR_REQUIRED` unless local Tesseract OCR is
   enabled.
5. Existing source-neutral ingestion persists immutable versions, chunks, embeddings, and citations.
6. Manual snapshots use `provenance_type=manual_snapshot`; strict HTTPS transport does not cause them
   to be labeled official legal evidence.

## Commands

Catalog only (safe default):

```bash
python -m legal_chatbot.demo_corpus.cli --catalog-only
```

Process all direct files without OCR:

```bash
python -m legal_chatbot.demo_corpus.cli
```

Enable OCR and resume only remaining processable/OCR-required records:

```bash
DEMO_CORPUS_OCR_ENABLED=true python -m legal_chatbot.demo_corpus.cli
```

Count-only report:

```bash
python -m legal_chatbot.demo_corpus.report_cli
```

For chatbot retrieval over all three snapshot source IDs, set:

```text
DEMO_CORPUS_ENABLED=true
DEMO_CORPUS_RETRIEVAL_SOURCE_IDS=VBQPPL,VNU,UEB
```

The full network/OCR batch was not auto-started because it downloads hundreds of PDFs and may run
for hours. It is resumable and idempotent through catalog states and immutable document snapshots.
