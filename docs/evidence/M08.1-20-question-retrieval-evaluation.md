## Methodology

1. Parsed `word/document.xml` directly from the DOCX ZIP with Python standard-library `zipfile` and
   `xml.etree.ElementTree`. The selector was `^Câu\s+(\d+)\.` and returned exactly Q1–Q20 in order.
2. Started the local Compose `db` service because it was stopped, waited for its health check, and used
   a `BEGIN READ ONLY` PostgreSQL session for every inventory and evaluation query. No migration was
   needed for the existing schema. The DB will be stopped after this evaluation because this run started
   it.
3. For every complete question, executed SQL equivalent to the raw repository's lexical query:
   `websearch_to_tsquery('pg_catalog.simple', question)`, latest version per document, `@@`,
   `ts_rank_cd DESC`, then chunk UUID ascending. The query selected only hit count and top-document
   metadata, never chunk text. It did **not** call `retrieve_and_persist`; `retrieval_runs` and
   `citation_records` remained at their read-only observed counts of 17 and 16.
4. Evaluated the canonical ceiling by normalizing the actual latest `title` and `document_number` values
   (NFC, collapsed whitespace, casefold) and checking whether an exact value was present in each
   question. This is the resolver's equality rule, not a generated planner plan.

## Coverage metadata and limits

The DOCX's own design-time reference list names the 2025/2026 university-education, civil-servant,
science/technology/innovation, and intellectual-property legal areas. It is used here **only as expected
coverage metadata**, never as answer evidence. None of those named reference documents is present in the
measured corpus inventory above.

This is not a legal-correctness benchmark: the DOCX has no gold answers, gold document IDs, or gold
scopes. Zero raw lexical hits prove only that this corpus/query combination has no lexical evidence; they
do not establish a legal conclusion. The raw query bypassed the service temporal guard in order to make
the requested read-only SQL measurement, so temporal labels identify a capability gap rather than a
service response code.

## Prioritized recommendations

1. Expand the explicit VBQPPL read-only allowlist and ingest the official current documents required by
   the benchmark's design-time coverage areas before evaluating planner recall or legal answers.
2. Keep test-fixture sources out of the demo/evaluation corpus, or filter them explicitly, so their
   metadata cannot be mistaken for legal coverage.
3. Preserve latest-version title/number metadata and provenance for each ingested official document;
   this is the prerequisite for useful exact canonical-anchor scoping.
4. Add controlled multi-document fixtures only after source coverage exists. Then measure raw versus
   planned retrieval with gold chunk/scope IDs; do not infer planner benefit from this zero-coverage run.
5. Treat explicit historical/current-effect requests as fail-closed until a sourced temporal/effectivity
   capability is implemented and measured.
